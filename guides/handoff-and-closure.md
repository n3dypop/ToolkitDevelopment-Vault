# 引継ぎと終了

## 引継ぎを作る条件

中断、外部待ち、長期化、担当交代が見込まれ、次の作業者が現在の会話を読めないときに作る。軽微な作業へ毎回作らない。

## 再開に必要な情報

引継ぎは結論から始め、次を含める。

- 目的と、ユーザーが決めた境界
- 正本の場所と基準版
- 現在の状態と、最後に成功した地点
- 今回実行した検証と結果
- 過去結果を継承しただけで、今回再実行していない検証
- 直近の失敗の原文要点と原因の切り分け
- 未完了事項、外部待ち、未検証事項
- 次に行う一つ目の操作と、その成功条件
- 実行してはいけない回避策や、追加承認が必要な操作

単なる日記にせず、別の作業者が安全に一手目を実行できる状態を目指す。

## 状態の表現

`done`、`failed`、`not-run`、`blocked`、`inherited` を区別する。環境がそろったこと、build が通ったこと、package が妥当なこと、実機で動いたことは別の状態である。

古い成功結果より最新の失敗が優先されるとは限らない。対象版や条件が異なる場合があるため、各結果に基準版を結び付ける。

## 閉じるとき

作業完了時は次を確認する。

1. 必須の利用経路と異常系を、リスクに見合う深さで検証した。
2. 公開物、作業物、原本が分離されている。
3. 文書、設定、名称、版、配布物が一致する。
4. Git の変更、commit、remote 反映を別々に説明できる。
5. 未解決事項が完了表現に隠れていない。

繰り返し使える教訓は引継ぎへ埋めたままにせず、確認後に DESIGN、AGENTS、ガイドへ移す。時点依存の結果は引継ぎか検証記録へ残す。
