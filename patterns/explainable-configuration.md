# 自動推奨を再利用可能な設定にする

## 使う条件

細かな引数を減らす自動設定を提供しつつ、利用者が理由を確認・編集し、同じ方針を再利用する必要があるときに使う。

## 解析と適用を分ける

1. 副作用の範囲を限定した解析で、推奨値と理由を返す。
2. 設定に schema version を持たせ、保存・編集・再読込できるようにする。
3. 明示指定、保存設定または自動推奨、従来の既定値の優先順位を決める。競合する指定は黙って選ばず拒否する。
4. 実際に採用した設定と、入力から決め直した値を確認できるようにする。

設定の適用範囲も契約にする。入力依存の範囲、出力先、認証情報、機器選択まで無条件に保存しない。解析と適用で必要な前提が変わった場合の扱いを明記する。

連続入力では、初回に固定する値と入力ごとに再計算する値を分ける。最初の入力を解析で消費した場合は処理へ戻し、先頭の欠落を防ぐ。固定値が後続入力へ合わなくなる条件と、利用者の上書き方法を説明する。

## 検証

未知の版・フィールド、不正な範囲、非有限値、過大ファイル、競合指定を扱う。保存と再読込の往復、手動指定の優先、旧既定値の維持、解析の副作用を確認する。

ヒューリスティックな推奨を最適解と呼ばない。自動化の品質は速度や形式の成立とは別に評価し、既存の保存設定を新版の推奨で無断変更しない。

## 使わない条件

少数の明快な引数で十分な処理や、入力ごとに人が判断すべき不可逆な操作へ、設定プロファイルを一律に導入しない。

## 確認方法

- 選ばれた値と理由を再現できる。
- 設定の版、優先順位、上書き、失敗条件が明確である。
- 解析・適用・実行の副作用と、品質の未検証範囲を説明できる。

[ソース台帳](../catalog/SOURCES.md)の SRC-014 から抽出した。元の推奨閾値や製品固有の設定名は含めない。
