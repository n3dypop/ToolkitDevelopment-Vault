# 複数の表示面で状態の意味を揃える

## 使う条件

常設表示、コマンド応答、通知、プレビュー、集計が同じ状態を表し、用語や対象の食い違いが起きるときに使う。

## 表示より先に意味を決める

- 表示する対象、期間、状態、確度を一度選び、見出し・本文・通知へ渡す。
- 「対象が存在しない」「観測がない」「値がゼロ」「予測上の問題がない」を別の状態にする。
- 実測値、推定配分、予測を区別する。観測数や期間を超えた精度を表示しない。
- 表示基準を一つ選び、用語、期間、色の意味、欠損値、順序を共通化する。
- プレビューも本番と同じ生成処理を通す。実装・検証していない操作部品を表示しない。

## 構造と見た目を検査する

構造テストでは対象状態、フィールドの順序、欠損値、長さ制限、重要度、動的な見出しを確かめる。文章全体の完全一致へ過度に依存せず、指定されたコピーだけ必要に応じて固定する。

実表示では狭い画面、折り返し、長い日時・数値、最長の見出し、値なしを確認する。構造テストが通ったことを、外部クライアントでの見た目の確認と同一視しない。

## 使わない条件

独立した異なる状態を表す画面へ、同じレイアウトや文言を一律に強制しない。表示の数が少ない段階で汎用 UI 基盤を先に作らない。

## 確認方法

- 同じ入力状態が各表示面で同じ対象と用語を選ぶ。
- 存在しない状態と不足した観測が別表示になる。
- プレビューと通知の生成経路、技術検査と実表示確認を区別できる。
